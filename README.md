# 公路巡检记录服务

按“公路 + 日期”接收巡检明细 CSV，存入 SQLite；支持将一天的数据按整米里程切点拆成两份分区，
按日期与里程范围导出 CSV。

## 快速启动（Docker Compose）

```bash
export SECRET_KEY="$(openssl rand -hex 32)"
docker compose up --build -d
# 打开 http://localhost:8000
```

`SECRET_KEY` 必须设置（用于会话与 CSRF 签名），未设置时 `docker compose` 会直接报错。
数据库保存在命名卷 `inspection-data` 的 `/data/inspection.db`，容器重建不丢数据。
健康检查：`GET /healthz`。

停止：`docker compose down`（保留数据卷）；清空数据再加 `-v`。

## 本地运行（无 Docker）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export SECRET_KEY="$(openssl rand -hex 32)"
export DATABASE_PATH="$PWD/data/inspection.db"
python -m inspection        # 开发用单进程；生产见 Dockerfile 中的 gunicorn 命令
pytest                      # 运行测试
```

## CSV 格式

上传单个公路一天的明细，必须有表头，包含三列（中英文列名均可）：

```
记录号,整米里程,病害等级
A-001,1200,轻
A-002,1350,重
```

* `整米里程` 必须是非负整数（不接受 `+1`、`1_000`、小数）。
* 文件编码支持 UTF-8（含 BOM）与 GB18030；分隔符支持逗号/分号/制表符。
* 若表头列名无法识别，会明确提示；确实没有表头时按上述列顺序解析（首行里程须为整数）。
* 任一结构性错误（缺列、空值、非整数等）会整份拒绝并给出物理行号，不写入任何数据。

## 业务规则

### 补报与冲突

* 同一公路、同一天、同一记录号，且里程与等级完全一致：视为原样补报，只保留一次，不重复写入。
* 同一记录号内容不同（与库中已有记录冲突，或同一文件内自相矛盾）：整份文件拒绝，逐条列出冲突。
* 补报在拆分搬移期间同样有效：新记录照常写入当前有效（原）分区，切换后落入对应新分区，不会丢。

### 分区拆分

* 每天初始为一个分区 `[0, +∞)`。
* 拆分点必须严格落在某个有效分区内部（`lo < cut < hi`）；里程等于切点的记录归**右侧**分区。
* 新分区区间为半开区间 `[lo, cut)` 与 `[cut, hi)`，可继续对任一份再拆分。
* 搬移分两阶段：
  1. **复制（有界快照）**：拆分开始的写事务里固定高水位 `copy_upto_id`（原分区当时的最大
     `records.id`），分批只复制 `id <= copy_upto_id` 的明细。复制批数在拆分开始时即确定，
     复制期间持续到达的补报 `id` 更大，不会被追读，因此不会出现“补报赶上进度就一直追新明细、
     迟迟不能切换”。影子分区对读写不可见，原分区继续接收补报与下载，切换前从原分区可下载全部
     已确认明细。
  2. **切换**：进入切换事务前，先用一个独立写事务把复制期间的补报全部补拷进 `split_staging`
     （“归档所需补报先备齐”）；随后单个 SQLite 写事务做最后的幂等增量扫尾、条数校验、删除原行、
     写入两个子分区并翻转状态。读者只会看到“切换前的一份”或“切换后的两份”，每条恰好一份，
     不会重、不会漏。

### 下载

* 按公路、日期、`start..end`（含端点；`end` 留空表示到无穷）导出。
* 只读取与请求里程范围相交的有效分区。
* 下载在单个 SQLite 读事务（WAL 快照）中完成：若下载过程中发生拆分切换，仍按**下载开始时**
  的分区布局读完，结果一致。
* 输出 UTF-8 BOM，便于 Excel 直接打开中文。

### 中断与重试

* 切换前任何失败/进程被杀：影子分区与暂存数据被丢弃，原分区保持完整、可查、可下载。
* 任务记录为 `failed`，页面的“最近拆分任务”可见原因。
* 进程重启或下一次拆分尝试（自动回收陈旧任务）都会清理残留，随后可直接重试拆分。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 选择路段/日期，查看分区、上传、拆分、下载 |
| POST | `/upload` | 表单：`road`、`date`、`file` |
| POST | `/split` | 表单：`road`、`date`、`cut` |
| GET | `/download` | 查询：`road`、`date`、`start`、可选 `end` |
| GET | `/healthz` | 健康检查 |

所有 POST 都需要页面会话中的 `csrf_token`。

## 数据模型

* `partitions`：路段/日期/`[lo, hi)`/状态（`active`、`shadow`、`retired`）、`split_state`。
* `records`：唯一键 `(road, date, record_no)`；触发器保证记录的里程落在所属分区区间内。
* `split_jobs`：切点、状态（`copying`/`switched`/`failed`）、已复制条数、错误信息。
* `split_staging`：复制阶段暂存，切换或回滚后清空。

## 已知限制与未完成项

* **Docker 未在本机实际执行**：开发环境没有 Docker CLI/守护进程，`docker compose up` 未运行过；
  Dockerfile 与 Compose 文件已按可构建方式编写并做过 YAML 结构校验，首次部署请以构建结果为准。
* 单个 SQLite 写者：上传串行写入，适合单路段/中低并发；大规模并发需换 PostgreSQL。
* 拆分复制阶段只处理拆分开始时的快照，批数固定、随快照条数线性变慢（分批提交以避免长时间持锁），
  期间持续补报不会延长复制；切换前另有一次集合式补报备齐 + 切换事务内的轻量扫尾。
  期间可正常上传与下载；拆分不设进度条，只能刷新页面看任务表里的“已复制”数。
* 下载在内存中生成整份 CSV（含 `send_file`），超大导出应改为流式。
* 同一公路同一天只允许一个拆分同时进行（`flock` + 唯一索引），并发拆分请求会收到“请稍后重试”。
* 未做用户认证/权限与路段级授权：页面上的公路名是自由输入，任何能访问页面的人都能上传/拆分/下载
  任一公路；养护员“只取自己路段”的限制需由部署方在反向代理或后续登录模块实现。
* 未删除/修正已收记录：本版本只提供“补充上报、冲突拒绝”，纠错需求未实现。
* 未实现分区自动合并、批量拆分或按里程段批量导入。
